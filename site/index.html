Your CLIs, not imitations

Harness Relay never calls a model API. It starts the claude, codex and grok you already have, with their own tools, sessions and logins, passes each agent the messages it hasn’t seen yet, and streams everything into one chat. OpenCode, Goose, Cline, OpenHands and Pi are started the same way, on the model backends you set up.

Open-source agents, on your own model

OpenCode, Goose, Cline, OpenHands and Pi join a team like the other three. They run on the model backends you set up in Settings: an API key for OpenAI, Anthropic or xAI, or your own OpenAI-compatible endpoint, such as vLLM, Ollama, LM Studio or llama.cpp.

Below full access, each of them, with everything it starts, runs in Harness Relay’s own OS sandbox. It writes only its own temp folder and its own sessions, which no other conversation’s agent can read or change, and in edit mode the working directory and the chat’s attachments too. It reaches the run’s model backend without asking; other hosts are asked about, except this computer’s own addresses, a few the agent contacts by itself and any past the 30th in a run, which are refused. Approvals come as the same cards in the chat.

Your keys, or your own endpoint

Give a member its model as backend/model: openai/gpt-5.4-nano, or your endpoint’s id and a model name, such as homelab/muse-glimmer-30b-nvfp4. Keys go to your OS credential store, and each run gets only its own backend’s key.

These CLIs take API keys only: the Claude subscription and Grok’s sign-in cannot be used by them. Claude Code and Grok themselves keep using their own sign-ins.

Choose how they take turns

Each conversation has its own rules: who speaks, in what order, and when it ends. Address anyone with an @mention and only they reply.

Roundtable

Agents speak in order, and each sees what earlier speakers said. Set one to five rounds; the run ends early when everyone in a round replies [PASS].

Good for discussions, reviews and refining an answer.

Parallel

Everyone answers at the same time, on their own. Later rounds see the earlier answers. With edit access each agent works in its own git worktree, and you apply the result you like.

Good for comparing approaches and getting independent opinions.

Relay

One agent at a time. An agent hands the floor to a teammate by @mentioning them; if it mentions nobody, the floor returns to you. You set the maximum number of hand-offs.

Good for pipelines: plan, implement, review.

A team for every question

The lead agent picks it. For each new question, it reads the question, the conversation so far, the current team and every template in full. Then it keeps the team, uses a template as it is, adapts one, or designs a new team, and says why. You confirm before the team answers, or let it answer right away.

You design the templates. Give each agent a position (architect, builder, reviewer, skeptic), pick its model and reasoning effort, and set the speaking order. Up to eight members, several on the same CLI if you like. A team the lead agent designed can be kept as a template in one click.

Runs on your machine

Nothing is hosted. The server listens on your computer only, and agent replies cannot make your browser load remote content.

  • Bound to 127.0.0.1 and takes only browsers you signed in; cross-site requests are rejected.
  • Below full access, Claude Code’s, Codex’s and Grok’s commands run in their CLI’s own OS sandbox: they write only in the working directory, and can’t read your browsers’ folders or Harness Relay’s data.
  • The five open-source agents, and everything they start, run in Harness Relay’s own sandbox (sandbox-runtime: Seatbelt on macOS, bubblewrap on Linux, a filtering proxy for the network): the same folders are out of reach, each member’s sessions are its own, and only the run’s model backend is reachable without asking. If it can’t start, they don’t run; on native Windows they run only with full access.
  • Git snapshots for every turn that edits; parallel agents in their own worktrees.
  • API keys and MCP server tokens in your OS credential store: macOS Keychain, Windows Credential Manager or Secret Service.
  • Your conversations live in one SQLite file; Harness Relay publishes one only when you share it as a link.

Quick start

  1. Install what it drives

    • Any of the CLIs: Claude Code (claude), Codex CLI (codex), Grok CLI (grok)
    • Or the open-source ones (versions tested): OpenCode (opencode-ai 1.19.5), Goose (block-goose-cli 1.58.1), Cline (cline 3.0.74), OpenHands (openhands 1.16.0), Pi (@earendil-works/pi-coding-agent 1.5.1, Node.js 22.19 or newer), with an API key for OpenAI, Anthropic or xAI, or your own endpoint. Below full access they run in a sandbox that needs Node.js 22.12 or newer, and on Linux also bubblewrap, socat and ripgrep.
    • Git, for edit and parallel modes. Nothing else: the app brings what it runs on

  2. Download and open it

    macOSmacOS 13 or later · Apple Silicon · .dmg Your system WindowsWindows 10 or later, x64 · .exe Your system Windows on ArmWindows 10 or later, Arm64 · .exe Your system Linuxx64 · .AppImage Your system Linux on ArmArm64 (aarch64) · .AppImage Your system

    All installers are on the releases page.

    On macOS, drag Harness Relay to Applications; on Windows, the installer sets it up for your user; on Linux, make the AppImage executable and run it. The installers are not signed yet, so the first time: on macOS, System Settings → Privacy & Security → Open Anyway; on Windows, More info → Run anyway.

  3. Sign in, then chat

    Harness Relay opens the chat in a window of its own, signed in, and stays in the menu bar (or the system tray) when you close it, so your phone can still reach it. Under Settings & sign-in, check that each agent is signed in, or, for the open-source agents, add an API key or your endpoint under Model backends. Then New chat: choose the working directory and permission, and ask your first question.

  4. Open it on your phone

    Optional. Install Tailscale on the computer and on the phone, then choose Share with your phone (Tailscale)… in Harness Relay's menu. It shares the server with your tailnet and shows the https:// address to open on the phone.

    Sign the phone in with a code from Settings → Signed-in browsers → Sign in another device on the computer. Only devices in your tailnet can reach it, and the server stays on 127.0.0.1. To add it to the home screen: Share → Add to Home Screen in Safari on iPhone, ⋮ → Install app in Chrome on Android.

    Step by step, with keeping it running and troubleshooting

On a server without a desktop, or working on Harness Relay itself? Run it from source with Node.js 22.13 or newer: npm start, or npm run dev while you change it.
