交給團隊的五件事

Harness Relay 是任務助理：你說要做什麼，首席 agent 就為它設計團隊，你手上的 coding agent 在你的電腦上一起完成。以下每件事都是實際執行的錄影，執行的 agent 列在各段裡，agent 工作的段落加速播放。

一個 bug 三種修法 查資料做決定 接力寫版本說明 分析試算表 晨間簡報

一個 bug 三種修法，留下最好的

測試沒過，只有一種修法等於用猜的。那就要三種：在平行模式下，每位 agent 都在自己的 git worktree 裡工作，修法不會互相干擾，也不會動到你的檔案。每則回覆都列出改了哪些檔案；你看完差異，把想要的那個套用到工作目錄，不會自動 commit，再用你慣用的工具檢查。

你問的

測試沒過：帳單無法整除時，splitBill 會多算或少算一分錢。請 Claude Code、Codex 和 Grok 平行修好它，每位在 Harness Relay 給它的 git worktree 裡修，並在那裡跑 npm test。

用到的功能

  • 平行模式。 大家同時、獨立回答，每位各有自己的 worktree。 對話規則
  • 可編輯權限。 agent 可以修改工作目錄裡的檔案、執行測試；超出的動作會先問你。 核准
  • 差異與套用。 改了檔案的回覆會列出檔案和 diff；「套用到工作目錄」把一個結果複製到你的工作目錄，不會 commit。 檢視與套用修改

查資料做決定，附上來源

不是每件事都是寫程式。問一個需要查資料的問題，agent 會自己上網搜尋、讀文件，再以圓桌輪流回應彼此的論點，全程唯讀。你得到附上參考連結的比較與建議；首席 agent 的審閱則標出他們意見不同的地方，以及哪些該由你親自確認。

接力寫版本說明

寫東西分幾輪會更好。在接力模式下一次一位發言，用 @ 交棒：這裡第一位根據上個標籤之後的 commit 起草版本說明，下一位改寫給使用者看，最後一位逐行對照 commit 查核。檔案就在你的工作目錄裡，「檔案」會顯示排版後的樣子。

每天早上，整理信件和行事曆

把重複的工作交給團隊。自動任務每個工作日 08:30 送出它的訊息；agent 用 Harness Relay 自己的工具讀你的信和行事曆，告訴你今天有哪些事需要你，並寫好回信。他們的回合裡什麼都不會送到別人那裡：每封信都在待送出匣逐欄列出，等你按「送出」。

錄影時用的是同一台電腦上的替身郵件與行事曆伺服器，裡面的信件和行程都是虛構的。

你問的

每個工作日早上，用 Harness Relay 的郵件和行事曆工具：讀昨天以來的新信和今天的行事曆，告訴我今天有哪些事需要我。需要回覆的信，用 mail_send 寫好簡短的回信：它不會自己寄出，每封回信都在待送出匣等我按「送出」（無人值守的執行不能存草稿）。每個會議邀約，都在回信裡提一個空檔。Claude Code 讀信，Codex 看行事曆。

用到的功能

  • 自動任務。 在設定的時間、你按「立即執行一次」、某件事發生（收到新郵件、行程即將開始、GitHub 上新的 pull request 或失敗的 CI、檔案出現或變動），或有程式呼叫它的 webhook 時執行；沒人看著時，超出權限的動作一律拒絕。 自動任務
  • 郵件與行事曆。 Harness Relay 自己的工具，用應用程式專用密碼連上你的帳號；Microsoft 365、Outlook.com 與 Google 的行事曆和郵件則改在瀏覽器裡登入。密碼與權杖都留在作業系統的憑證儲存區。 Harness Relay 的工具
  • 待送出匣。 郵件或邀請絕不會在 agent 的回合裡送出：它會以卡片等著，直到你按「送出」或「捨棄」。 核准
