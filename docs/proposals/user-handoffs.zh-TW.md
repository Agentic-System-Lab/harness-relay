# 只有使用者能做的步驟：密鑰、固定指令與互動

**狀態。** 已完成：S（密鑰卡）、A（固定指令：試跑、待送出匣、自動任務）、B1（互動指令）、B2 的交出對話瀏覽器（同一台電腦開視窗、從別處用畫面串流；由瀏覽器工具 `browser_hand_over` 觸發，而不是回覆區塊）、檔案面板的編輯和上傳（第 2 項），以及步驟卡（第 10 項）；[架構](../architecture.zh-TW.md#密鑰與固定指令)、[使用說明](../user-guide.zh-TW.md#密鑰與固定指令)與[開發者說明](../developer-guide.zh-TW.md)描述了它們。還沒做：B2 只給使用者的瀏覽器和**把選取的文字存成密鑰**、要一直執行的程式（第 7 項）、接收外部 webhook（第 8 項），以及下面的待決問題。下面的名稱是設計時的名稱；實作後的名稱以那些文件為準。

## 從哪裡來

在一段對話裡，團隊透過 Threads API 設定自動發文。agent 寫了一支腳本 `setup_token.py`，用隱藏輸入詢問存取權杖（權杖是短期的時，再詢問 App Secret 來交換），把權杖存進 `.secrets/threads.env`（資料夾 700、檔案 600、git 會忽略），接著寫了 `verify.py`，以及從 `queue.csv` 取下一筆核准貼文發出的 `post.py`。使用者必須離開 Harness Relay，到伺服器所在的電腦開終端機執行 `setup_token.py`：聊天裡沒有任何地方能接收密鑰而不留下它，agent 執行的指令也沒辦法讓人輸入。之後遇到的都是同一類問題：定時發文每次都要一輪 agent（那段對話裡 agent 每輪花 $0.09 到 $0.63），新增貼文要請 agent 改 `queue.csv`，也沒有辦法讓使用者在每篇發出前核准。

## 現在有什麼

- **提問。** agent 在回覆結尾加上 `[ASK_USER]`（`src/shared/ask.ts`），團隊就會等待；回答是一則一般訊息，存在資料庫裡，會出現在分享頁，也會進入 agent 的提示詞。
- **agent 執行的指令。** 每個 CLI 用自己的 shell 工具執行指令。Harness Relay 看得到 CLI 回報的指令內容，但碰不到那些行程的輸入，所以等待輸入的指令（密碼、`y/N`、登入代碼）沒辦法回答。
- **不用終端機的登入。** `CliLogin`（`src/server/login.ts`）用管線（pipe）執行程式，顯示它的輸出並挑出其中的網址和代碼，再把使用者貼上的內容寫進它的輸入（一行，去掉前後空白）。它執行設定裡 agent CLI 自己的登入，以及 Relay 用到 gh 的地方的 gh 登入（分享、發布、問題回報、常用 App 的 GitHub 列）。它沒有終端機：讀 `/dev/tty` 的程式（ssh 的 passphrase、沒有 `-S` 的 `sudo`）沒辦法透過它回答。
- **Relay 自己執行的指令。** 團隊檢查的指令（`src/server/checkCommands.ts`，`runCheckCommand()`）透過一段固定的 shell 腳本執行，指令內容從環境變數讀取，環境是它自己的（`checkEnv()`：沒有 API 金鑰、沒有權杖），低於完全存取時在 Harness Relay 自己的沙箱裡執行：除了使用者為那條指令打開的開口（macOS 上是所有本機埠，Linux 上是所有 Unix socket）之外沒有網路，只能寫入工作目錄和這次執行的暫存資料夾，受保護的路徑讀不到，沙箱無法啟動就不執行。在原生 Windows 上不論權限都不執行。一輪的變更動到指令提到的檔案或測試、lint 設定（`namedFiles()`、`checkConfigFiles()`、`CONFIG_FILE`）時，要等使用者同意才執行那些指令，沒人看著的執行則直接判為失敗（orchestrator 的設定檔關卡）。同一個沙箱已經能依主機過濾開源 agent 的網路（透過它的 proxy 的 `allowedDomains`，`src/server/relaySandbox.ts`）。
- **受保護的讀取。** 低於完全存取時，CLI 的沙箱讀不到瀏覽器的資料夾、Relay 的資料庫、`data/tmp` 和 `data/browser`（`src/server/protect.ts` 的 `protectedReads()`；原生 Windows 上沒有）。Relay 沙箱每次執行的資料夾（`data/relay-sandbox/<id>`）只對開源 agent 隱藏（`src/server/agents/open.ts` 的 `privateRoots()`）：Claude Code、Codex 和大部分其他 CLI 讀得到。
- **待送出匣**（`src/server/outbox.ts`）：Relay 自己的工具要送給別人的東西（郵件、邀請、Slack 或 Teams 貼文、Docs 或 Obsidian 的寫入）會先放在這裡，等使用者按**送出**。呼叫 API 的腳本只是一條指令，不是這些工具，所以永遠不會進待送出匣，而偵測發布類指令只能盡力而為（`isPublishCommand()`）。
- **自動任務**到時間會送一則訊息給團隊（`src/server/scheduler.ts`），再由 agent 做事。自動任務的執行中，超出對話權限的動作會被拒絕，除非使用者在那個對話裡設成**一律允許**、選了**詢問我**，或用**替我核准**（首席 agent 先核准它判斷安全的）。自動任務只在 Relay 執行時運作，每個對話一個，間隔以整小時計。自動任務能等待的事件只有新郵件、即將開始的活動、pull request 或失敗的 CI，以及工作目錄裡的檔案（`src/server/watch.ts`）。自動任務的 webhook（`POST /api/hooks/:id`）必須連得到，而伺服器除非 `HOST` 另有設定，只綁在 `127.0.0.1`；手機要透過[遠端存取](../remote-access.zh-TW.md)才連得到。
- **檔案面板**（`src/server/files.ts`）：瀏覽、預覽、下載和 ZIP，每個路由都是 `GET`。附件是跟著訊息送出，不會放進工作目錄的某個路徑。
- **瀏覽器工具**（`src/server/browser/`）：每個對話一個無頭 Chromium（`--headless=new`），有自己的空白設定檔，對話刪除時一起刪除。使用者只看得到回覆裡的截圖，看不到瀏覽器本身。
- **OAuth**（`src/server/oauth/`）：Microsoft 與 Google 帳號，以及工具庫裡的 HTTP MCP 伺服器。其他服務的 OAuth（使用者在 Meta、X、LinkedIn 註冊的 App）沒有地方放。
- **快照**（`src/server/workspace.ts` 的 `snapshot()`）會把未追蹤的檔案收進提交，只排除忽略規則列到的，保存在 `refs/harness-relay/…` 底下。agent 寫了密鑰檔卻沒有加進忽略規則，它就會進到儲存庫的物件裡。
- **Harness Relay 自己的工具**只在完全存取時才給 Grok、Muse Code、Goose、Cline、OpenHands 和 Pi（`GATEWAY_FULL_ACCESS_ONLY`）。回覆結尾的區塊在每個 CLI、每種權限下都能用：`[ASK_USER]`，以及適用時的 `<remember>` 和 `<progress>`（開啟長期記憶時、追蹤目標時）。

## 設計

分成三部分。S 接收密鑰；A 帶著密鑰執行固定指令；B 讓使用者接手只有他能做的事。

### S. 密鑰卡

agent 在回覆結尾為每個需要的密鑰加一個區塊：

```text
<secret name="THREADS_ACCESS_TOKEN" label="Threads 存取權杖">從 App 的 User Token Generator 取得。</secret>
```

團隊會像 `[ASK_USER]` 一樣等待。聊天裡出現一張卡片，每個密鑰一個遮蔽的輸入框，說明是哪個 agent 要的、哪些固定指令（A）會拿到它、值不會進入聊天或 agent 的提示詞，以及 Relay 從不需要使用者自己帳號的密碼。按**儲存**後送到伺服器（`POST /api/conversations/:id/secrets`，在 `/api/` 底下，經過同樣的檢查）；伺服器依工作目錄和名稱，透過 `SecretStore` 保存（`openSecretStore()`：作業系統的憑證儲存區，沒有時加密存在資料庫裡）。沒有任何路由會把值傳回來。訊息只記下「已提供 THREADS_ACCESS_TOKEN」，從不記值：不進訊息、SSE、分享頁、AgentsView、長期記憶或通知。簡報會列出這個資料夾有哪些名稱（從不列值），並要求 agent 用這個區塊來要，不要在聊天裡要密鑰，也不要請使用者到終端機執行腳本。名稱限 `[A-Z_][A-Z0-9_]*`；設定裡依資料夾列出，可以**取代**和**刪除**。

這些值不會交給任何 agent 的 CLI、環境變數或工作目錄，只交給有寫明要用它們的固定指令（A）。

### A. 固定指令

固定指令是使用者為某個工作目錄儲存的一行指令，連同它能連的主機和它拿得到的密鑰：

```text
<command name="post" hosts="graph.threads.net" secrets="THREADS_ACCESS_TOKEN">python3 post.py</command>
```

agent 用這個區塊提議；聊天裡出現一張卡片，列出指令、資料夾、主機和密鑰，由使用者按**儲存**（或先修改）。光有區塊不會執行任何東西。

**怎麼執行。** 跟檢查指令一樣（`runCheckCommand()`）：固定的 shell 腳本、自己的環境，低於完全存取時在 Harness Relay 自己的沙箱裡，只能寫入工作目錄和它的暫存資料夾，受保護的路徑讀不到；和檢查指令不同的是，網路只開放給它自己的主機（沙箱的 `allowedDomains`）。和檢查指令一樣，在原生 Windows 上不執行。

**密鑰放在檔案裡，從不放進環境變數。** 一個在這次執行暫存資料夾裡的 dotenv 檔，由 `RELAY_SECRETS_FILE` 指出位置。不用環境變數的原因：同一個使用者的其他行程讀得到一個行程的環境變數，而且 `PATH`、`LD_PRELOAD` 或 `RELAY_CHECK_COMMAND` 這類名稱會改變指令啟動的方式。A 需要讓其他 CLI 也讀不到 Relay 沙箱每次執行的資料夾（`relaySandboxRoot()`、`relaySandboxHostRoot()`），用一份它們自己的清單交給它們的沙箱（Claude Code、Codex、Grok、Copilot 和 Muse Code 的沙箱；Cursor 的拒絕規則；Antigravity 的拒絕回應），讓指令執行期間沒有任何 CLI 讀得到這個檔案。不能透過 `protectedReads()`：Relay 沙箱把那些路徑當成任何執行都不能讀寫的地方，連它自己的資料夾也是，所以開源 agent 才另外用 `privateRoots()`。簡報會要求 agent 讓腳本自己讀這個檔案，從不把值當成參數傳給另一個程式（`curl -H …`），因為 `ps` 看得到參數。執行完後，若檔案裡它擁有的名稱換了值（例如權杖續期了），就存回去，檔案隨暫存資料夾一起刪除。

**輸出會遮蔽。** 輸出在送到任何地方之前（它的卡片、聊天、agent、通知），Relay 為它保存的每個值都會換成 `••••`，包括剛存回去的值。這只認得原樣的值，認不出編碼過的。

**鎖定它的程式碼。** 儲存時會把工作目錄裡的程式碼保存成一份快照：指令提到的檔案、其他所有副檔名在 `namedFiles()` 認得範圍內的檔案（所以腳本引入的模組或被偷放的 `json.py` 也算），符合 `CONFIG_FILE` 的設定檔，以及 `package.json`。其中任何一個改過，下一次執行就會先問使用者並顯示差異；自動任務的執行在那之前會被拒絕，並告訴團隊，就像檢查指令的設定檔關卡一樣。指令寫入的資料（`queue.csv`）不鎖定。在 macOS 和 Linux 上低於完全存取時，對於 agent 在沙箱裡執行的指令，agent 因此讀不到密鑰（它不在 agent 沙箱讀得到的任何資料夾或環境裡），鎖定的程式碼改過，在帶著密鑰執行之前會先顯示差異，而執行的程式只連得到它的主機。快照沒收的就沒有鎖定：被忽略的資料夾，例如 `.venv/` 和 `node_modules/`，編輯權限的 agent 寫得到，腳本也會從那裡載入程式碼；還有 `namedFiles()` 不認得的檔案種類（`.pyc`、`.so`、`.node`、Perl 的 `.pm`）；見待決問題。腳本不會把密鑰寫進工作目錄（agent 讀得到那裡），靠的也是鎖定；遮蔽只管輸出。使用者允許在沙箱外執行的指令，以使用者的權限執行，讀得到這個檔案，就像現在它讀得到 Relay 的資料庫和 `secrets.key`；完全存取的每個 agent 也一樣。卡片會說明這點。

**用在哪裡。**

1. 卡片上的**試跑**，由使用者執行（例如這一次加上 `--dry-run`），輸出顯示在卡片裡。
2. **自動任務**：自動任務的動作可以是「執行這個固定指令」，而不是一則訊息。它不呼叫模型。結束碼 0 表示沒事；保留給它的一個結束碼（例如 10）表示有新東西，輸出交給團隊；其他結束碼表示失敗，輸出以失敗的形式交給團隊。這也能做輪詢：每小時執行一次、檢查某個 feed 或 API 的指令。
3. **待送出匣**：agent 提議用某個輸入（貼文內容）執行一次已儲存的指令，輸入從指令的 stdin 傳入，從不放在指令列上。待送出匣的卡片列出輸入和指令；按**送出**就執行一次。自動任務也能這樣做（先擬稿，再由使用者在手機上核准）。

### B. 使用者接手

**B1. 互動指令。** agent 用一個區塊提議需要使用者的指令（`gcloud auth login --no-launch-browser`、`npm login`）。卡片列出指令、資料夾，並說明它以使用者的權限、在 agent 的沙箱之外執行；按**開始**才執行，自動任務的執行裡從不執行。它的啟動方式和檢查指令一樣：固定的 shell 腳本從環境變數讀取指令，環境只有 `checkEnv()` 保留的那些變數（從不用伺服器的環境，那裡可能有 API 金鑰），但不加它的 `CI=1`，因為很多程式看到它就會跳過提問，在它自己的空資料夾裡執行；只有使用者選擇時才在工作目錄執行，這時卡片會列出那裡它可能載入的設定檔（`.npmrc`、`.env`…），因為 agent 寫得到這些檔案。它的輸出會挑出網址和代碼，並像 A 一樣遮蔽，卡片裡也是；程式若回顯隱藏輸入的內容，也會遮蔽。卡片有一行輸入框和**隱藏我輸入的內容**開關、取消按鈕和時間上限；輸入的內容照原樣送出（`CliLogin.write()` 會去掉前後空白）。對於透過輔助程式詢問密碼的程式，B1 提供自己的輔助程式：一支內容固定的程式，唯一的參數是提示文字，從 B1 的環境讀取要向哪裡詢問，再向卡片要一行隱藏輸入；它和 hook 的程式（`hookShim.ts`、`hookProgram()`）一樣需要 Node，而桌面版的 `PATH` 上不一定有。它用在 `sudo -A` 搭配 `SUDO_ASKPASS`、ssh 搭配 `SSH_ASKPASS` 和 `SSH_ASKPASS_REQUIRE=force`（OpenSSH 8.4 以上）、git 搭配 `GIT_ASKPASS`。只有使用者按**送給團隊**，輸出才會給 agent。登入存下的東西會放在程式自己存放的地方，通常是使用者的家目錄（`~/.config/gcloud`、`~/.npmrc`），低於完全存取的 agent 讀得到那裡：卡片會說明這點。仍然不支援：需要終端機的程式（全螢幕程式、會檢查有沒有終端機的提示）。行程沒有終端機，所以 Python 的 `getpass` 會退回讀它的輸入，可以用。原生 Windows 沒有 `/bin/sh`，所以 B1 一開始不在那裡執行（見待決問題）。

**B2. 接手瀏覽器。** 頁面需要使用者時（登入、雙重驗證、驗證碼、同意畫面），agent 用一個區塊提出要求。無頭只是一個啟動參數（`src/server/browser/session.ts` 的 `--headless=new`）：同一個瀏覽器、同一個設定檔，也能開成有視窗的。所以 B2 用兩種方式之一顯示頁面：

- **在 Relay 執行的那台電腦上開視窗。** 那台電腦能顯示視窗時才提供（桌面版；已登入桌面的 macOS；有 `DISPLAY` 或 `WAYLAND_DISPLAY` 的 Linux；Windows），頁面看起來也在那台電腦上時優先選它（桌面版的視窗，或經由本機連線、以 `127.0.0.1` 或 `localhost` 開的頁面）。對話的無頭瀏覽器會關掉，同一個設定檔改用不帶 `--headless=new` 的方式開啟；卡片會說明視窗開在 Relay 執行的那台電腦上。在視窗裡，剪貼簿、輸入法、密碼管理器的貼上和硬體金鑰都能用，user agent 也是瀏覽器原本的。使用者關掉視窗，或在聊天裡按**完成**，視窗就會關閉；agent 下一次呼叫時，瀏覽器再以無頭方式開啟，帶著使用者登入的狀態。
- **畫面串流，在哪裡都能用。** 用在伺服器在別處時（homelab、codespace、透過遠端存取的手機）：聊天會開一個面板，用 Chromium 的畫面串流（`Page.startScreencast`）顯示頁面，再把使用者的點擊和按鍵送回去（`Input.dispatch…`）。

不論哪一種，所有連線仍然經過瀏覽器的 proxy 和它的主機檢查（低於完全存取時，使用者輸入的網址照常會詢問），下載和檔案選擇器仍然拒絕，瀏覽器也只用一個分頁，所以使用者開的新分頁會被關掉（視窗會說明這點）。這段期間 agent 的瀏覽器工具會等待。

使用者登入的狀態會留下來：agent 可以在這個對話的瀏覽器裡使用它，直到對話刪除，也讀得到那個帳號能顯示的任何內容（`browser_snapshot`）；卡片會在開始前說明這點。所以會顯示密鑰的頁面（權杖產生器）不在對話的瀏覽器裡開：

- **在同一台電腦上**，使用者用自己的瀏覽器打開它，再把值貼進 S 密鑰卡。
- **從別處連線時**，用**只給使用者的瀏覽器**：一個有自己設定檔的瀏覽器的畫面串流，沒有 agent 能操作或讀取，使用者關掉面板時就刪除。**把選取的文字存成密鑰**會由伺服器透過除錯管道讀取使用者在頁面上選取的文字（輸入框裡的也算），直接以 S 密鑰卡的名稱存起來：卡片只說明它是從頁面存下的，值從不以資料的形式送到瀏覽器（畫面串流的影像除外）。

限制：瀏覽器仍然透過除錯管道控制，網站可能還是看得出它被自動化控制（Google 的登入會不會放行這個視窗，要實測），而存在系統鑰匙圈裡的 passkey 可能不會出現（它帶著 `--use-mock-keychain` 執行）。透過畫面串流時還有：user agent 會表明它是無頭的，有些網站會拒絕這種瀏覽器（Google 的登入可能會；驗證碼可能更難過）；passkey 和硬體金鑰無法使用；有些按鍵可能送不過去（見待決問題）。

## 安全

- **密鑰的值**只會到 `SecretStore`，以及固定指令那次執行的檔案：從不進訊息、**儲存**之後的用戶端、指令列、agent 的環境或工作目錄。
- **這道防線只在 macOS 和 Linux 上低於完全存取時、對沙箱裡執行的指令成立。** 完全存取時 agent 以使用者的權限執行；使用者（或在替我核准下的首席 agent）允許在沙箱外執行的指令也一樣：Cursor 和 Antigravity 沒有沙箱，Claude Code 會要求在它的沙箱外執行指令。這時的防線就是那次核准，和現在 Relay 的資料庫及 `secrets.key` 一樣。原生 Windows 上固定指令不執行。
- **值從不放在指令列上。** 簡報要求腳本自己讀檔案。
- **低於完全存取時，它同時靠三件事：** 受保護的執行資料夾、鎖定的程式碼，以及指令的主機。遮蔽只是最後一道網，認得原樣的值。
- **B1 和 B2 以使用者的權限或登入狀態行動。** 開始前都會先顯示，自動任務的執行裡從不開始。顯示密鑰的頁面在使用者自己的瀏覽器，或 B2 只給使用者的瀏覽器裡開，從不在對話的瀏覽器裡開。
- **卡片的標籤和理由是 agent 寫的。** 每張卡片都會說明是哪個 agent 要的、誰會用到這個值，以及 Relay 從不需要使用者帳號的密碼。

## 步驟

1. S，以及 A 和它的**試跑**（分享的那段對話需要的部分），並讓其他 CLI 的沙箱讀不到 Relay 沙箱每次執行的資料夾。Relay 自己的密鑰不放在任何工作目錄裡，快照就永遠收不到。
2. A 用在自動任務和待送出匣。
3. B1。
4. B2：先做視窗，再做畫面串流和只給使用者的瀏覽器。

另外：檔案面板的編輯和上傳（2），以及步驟卡（10）。

## 考慮過但不採用的做法

- **頁面裡的終端機**（工作目錄裡的 shell，像預覽的終端機一樣用 xterm.js）。它能涵蓋更多第 6 項，但需要虛擬終端機（node-pty 之類的原生模組，桌面版和 Windows 也要），對任何登入的瀏覽器開放一個在所有沙箱之外的完整 shell，而且 Relay 的使用者大多不是工程師。B1 只執行使用者先看過的指令。
- **在 agent 執行的指令裡輸入。** 那些行程屬於 CLI，不屬於 Relay。
- **把密鑰放進 CLI 的環境變數。** 每個 CLI 把環境變數交給指令的方式不同；任何 `env` 都會把值放進模型的上下文；續期後的權杖也寫不回去。
- **把密鑰檔放在工作目錄裡**（分享的那段對話的做法）。低於完全存取的每個 agent 都讀得到，沒加進忽略規則就會被快照收進去，同步這個資料夾的工具也會複製它。
- **在聊天裡貼密鑰。** 存在資料庫裡、出現在分享頁、進入每個提示詞。
- **用 gateway 工具取代回覆區塊。** 有六個 CLI 只在完全存取時才拿得到 Relay 的工具；回覆區塊十二個都能用。
- **讓無頭瀏覽器看起來像有視窗的**（換一個 user agent）。這是在偽裝自動化的瀏覽器；使用者本人登入，正當的做法是開真的視窗。
- **使用者自己的瀏覽器和它的登入狀態。** agent 會拿到使用者登入的每個網站，而瀏覽器工具現在明確排除這點。
- **為每個服務的 OAuth 做一個 Relay 自己的 provider。** 服務太多，各有各的規則（Threads 要求不是 localhost 的 HTTPS 回呼網址，Relay 在 `http://127.0.0.1` 的回呼不符合）；S 和 A 讓使用者自己的腳本去做交換。

## 待決問題

- 密鑰和固定指令要依工作目錄還是依對話保存？每次開新對話的自動任務（`sendInNewChat()`）需要依資料夾；這樣同一個資料夾的兩個對話會共用。
- 鎖定資料夾裡所有程式碼和設定檔夠不夠？被忽略的資料夾（`.venv/`、`node_modules/`）不在快照裡，腳本卻會從那裡載入程式碼，有些程式碼也放在 `namedFiles()` 不認得的檔案裡（`.pyc`、`.so`、`.node`、`.pm`）：要連那些資料夾一起鎖定，還是在鎖定的快照副本上執行指令？
- 遮蔽只認得原樣的值，認不出編碼過的（base64、URL 編碼）；對付會把值編碼的腳本，鎖定程式碼是否足夠？
- 原生 Windows 上的固定指令：那裡沒有 Relay 自己的沙箱。
- B1 是否要用虛擬終端機（node-pty，或 macOS 和 Linux 上的 `script(1)`），處理需要終端機的程式？
- 原生 Windows 上的 B1：直接啟動程式本身，從不透過 `cmd.exe`。那裡 Python 的 `getpass` 讀的是 Windows 給行程的主控台，而不是它的輸入。
- 登入會跳回伺服器上的 `localhost`，但瀏覽器在別台電腦時：B1 是否要接收瀏覽器最後停在的網址，在伺服器上代為請求，而且只限它自己的行程監聽的埠？
- B2 的畫面串流：送不了哪些按鍵（輸入法組字、剪貼簿）？密碼欄位的值是否該出現在 `browser_snapshot` 裡？
- B2 的視窗：怎麼判斷頁面就在 Relay 執行的那台電腦上？SSH 通道也是經由本機連線、以 `localhost` 連進來，所以卡片一律說明視窗開在哪裡，並讓使用者改選畫面串流。
- B2 的視窗：透過除錯管道控制、帶著 `--use-mock-keychain` 的瀏覽器，Google 的登入和 passkey 能不能用？
- 除了卡片上的說明，還能怎麼避免 agent 的卡片要求不該要的東西（例如使用者自己 Google 帳號的密碼）？
- 第 7 項（要一直執行的程式）：由 Relay 監管的服務（啟動、停止、日誌），還是經使用者同意後交給系統自己的（launchd、systemd）？
